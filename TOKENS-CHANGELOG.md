# Tokens changelog

Migration notes for consumers of this design system's tokens: `colors_and_type.css`
(source of truth) and its generated `tokens.json` snapshot. This file tracks
**value/name changes to tokens themselves** — not every feature commit, which
already has its own entry in `CHANGELOG.md`. If a change here breaks a
downstream color/spacing assumption, it is called out explicitly with the old
and new value.

## Current token set

- **Source**: `colors_and_type.css`
- **Snapshot**: `tokens.json` (`tokenCount: 200`, `generatedAt: 2026-08-05T21:44:02.497Z`)
- **Docs**: `docs/theme-tokens.md` (full token table + contrast table + rail-color
  documentation, regenerated by `node scripts/generate-tokens-json.mjs && node
  scripts/generate-theme-tokens-doc.mjs`)
- **Live map**: `preview/theme-map.html` (grouped browsable view, same generator)

## How to log a future token change

Every commit that changes a token's **name** or **resolved value** (not just
which components consume it) must add an entry here, newest first, under a
new `## <date> — <short description>` heading, with:

1. **What changed** — token name(s), old value -> new value.
2. **Why** — the concrete defect or requirement (e.g. "failed AA at
   4.19:1 on --paper", "restyle from warm-paper to shadcn-neutral").
3. **Blast radius** — which consumers were re-verified (grep `var(--name`
   across the component sheets listed in `scripts/generate-theme-tokens-doc.mjs`'s
   `SHEETS` array is the authoritative check), and whether `npm run a11y` /
   `npm run lint:tokens` were re-run clean.
4. Re-run `node scripts/generate-tokens-json.mjs && node
   scripts/generate-theme-tokens-doc.mjs` in the same commit so
   `tokens.json`/`docs/theme-tokens.md`/`preview/theme-map.html` never drift
   from `colors_and_type.css`.

A token **rename** (not just a value change) additionally requires grepping
every consumer sheet for the old name and updating it in the same commit —
`scripts/lint-tokens.mjs` is the CI-facing guard against a stale reference
surviving a rename.

## History

Token-level changes prior to this file's creation are recorded in
`CHANGELOG.md` under their respective feature entries (search for
`feat(theme)`); the most significant is the 2026 "shadcn-neutral" restyle,
which repointed every primitive color (`--paper`/`--ink`/`--acid` and the
full `--green`/`--purple`/`--mascot`/status palette) from a warm-paper/
electric-lime identity to a neutral grayscale one, re-verifying WCAG AA
contrast on every re-pointed pair. Semantic token *names* were unchanged in
that restyle, so it did not require consumer-side edits — only the resolved
values moved.

- **2026-08-06** — Added this changelog. No token values changed in this
  commit; this entry documents the process going forward and records the
  current snapshot (`tokenCount: 200`) as the baseline every future entry
  diffs against.

- **2026-08-14 — "warm editorial" restyle: neutral grayscale → amber lead.**
  Full visual redesign of the paper/ink/accent triad, replacing the
  2026-07-30 shadcn-neutral grayscale identity with a warm cream/brown
  editorial identity and a confident amber accent. The multi-hue category
  palette (`--green`/`--purple`/`--mascot`/status tones) is untouched — only
  the neutral paper/ink/accent triad changed, using the same root-token-cascade
  mechanism as the prior restyle (change the root, every derived
  `color-mix()`/`var()` consumer updates automatically).

  **What changed** (old → new):
  - `--paper` `#FDFBF7` → `#FBF6EE`
  - `--paper-2` `#F2F0EC` → `#F1E9DA`
  - `--paper-3` `#E5E2DC` → `#E3D6BF`
  - `--ink` `#1A1A1A` → `#251C12`
  - `--ink-2` `#333338` → `#3D3125`
  - `--ink-3` `#525252` → `#5F5040`
  - `--ink-3-dark` `#4D4D52` → `#5A4B3B`
  - `--paper-3-dark` `#BEBEBE` → `#D8C9A8`
  - `--acid` (accent fill) `#262626` → `#8A5A0A`
  - `--acid-deep` (accent text) `#171717` → `#5C3B06`
  - dark-theme `--accent`/`--accent-bright` (both the `[data-theme=ink/dark]`
    block and its `[data-theme=auto]` media-query mirror, plus the
    `[data-accent=acid]` override) `#BFBFBF` → `#E8A93E`
  - `--ff-display` `system-ui, sans-serif` → `ui-serif, Georgia, "Times New

  **Why** — user-requested full visual redesign ("believe in yourself, change
  everything" → scoped to visual identity, architecture/kits/content
  structure kept intact per explicit instruction). Amber lead chosen as a
  confident, distinct-from-both-priors direction (neither the retired
  electric-lime "Acid Editorial" nor the outgoing neutral grayscale).

  **Blast radius** — all 32 consumer files (component sheets + kit HTML)
  re-verified: `npm run lint:tokens` clean (0 hardcoded-color violations,
  `lint-dark-parity` confirms both dark blocks stayed in sync), `npm run a11y`
  re-run live against all 23 kits — **0 blocking violations** (matches
  pre-restyle baseline exactly; every contrast pair hand-computed via the
  WCAG relative-luminance formula before landing, then confirmed by the real
  axe-core audit). Also fixed 18 files' hardcoded pre-CSS-load FOUC-guard
  hex literals (`ui_kits/*/index.html` + `_template` scaffold +
  `site/theme.mjs`'s `headExtra`), which had drifted stale across *three*
  palette generations (`#FFFFFF`/`#1A1A1A` — neither this restyle's values
  nor even the prior shadcn-neutral restyle's) since `lint-tokens.mjs` only
  scans `.css` files, not inline `<style>` blocks in `.html`.

  `node scripts/generate-tokens-json.mjs && node
  scripts/generate-theme-tokens-doc.mjs` re-run in this same commit; visual
  baselines regenerated via `npm run visual:update` (a palette redesign is
  expected to fail visual-regression checks against the old baseline by
  design — regenerating them is the correct response, not a bug).

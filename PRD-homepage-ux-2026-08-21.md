# PRD — homepage/showcase UX remediation (2026-08-21)

Source: a 68-item UX/copy/a11y audit of this repo's own marketing homepage
(`site/content/pages/home.yaml` → `dist/index.html`) plus a handful of
sub-kit pages (OS shell, dashboard). Re-verified against the live-rendered
page (not just source) before fixing anything — several items in the
original list turned out to already be fixed or never true; see "N/A"
entries below, each with the live evidence that refuted the claim.

Produced without `gm` (daemon still dead, same runner-swap deadlock as the
prior pass — see `PRD-remediation-2026-08-20.md`); continuing without it per
standing approval for this session.

**Build-pipeline finding, not a copy bug**: `dist/index.html` is generated by
an external tool (`npx flatspace@latest build`, reading `site/content/*.yaml`
+ `site/theme.mjs`), not by anything in this repo's own `scripts/`. The
committed `dist/index.html` was stale relative to current `home.yaml` before
this pass touched anything (its embedded JSON still had "19 kits" copy that
`home.yaml` had already moved past) — rebuilt fresh before doing any
comparison, and rebuilt again after every content edit in this pass. If a
future session edits `site/content/*.yaml` and doesn't see it reflected in
`dist/index.html`, this is why: run `npx --yes flatspace@latest build`.

**Live-verification finding**: `dist/index.html`'s importmap points at the
`@main` jsDelivr CDN build of the SDK, not local `dist/247420.js` — so
testing `dist/index.html` directly in a browser exercises the *last
published* JS, not this session's uncommitted component fixes. Verified the
JS-level fixes below (heading levels, sidebar markup, pill counts, empty
state) against a scratch copy with the importmap redirected to
`./dist/247420.js` locally, confirmed working, then discarded that copy
(never committed).

## Kit-count consistency (the recurring bug)

- **DONE, and fixed the root cause, not just the numbers.** The real count
  turned out to be **18** in the curated `home.kits.items` list (a prior
  merge collapsed "Community" into "Community app," dropping 19→18 with a
  code-number gap 16→18 that skipped 17 — renumbered cleanly to 16/17/18)
  and **23** for the *total* `ui_kits/` folder count used everywhere the
  copy means "every kit in this repo" (the a11y-scanned set, etc.) — these
  are two genuinely different counts serving different sentences, not one
  number written two ways.
  Root cause found and fixed: `site/theme.mjs` had two `.replace(/regex/)`
  calls meant to auto-sync a kit count into hero/feature-card prose at build
  time — both were **already dead** (the regex matched an old sentence shape
  that a prior session's copy edit had already moved past), so hero prose
  and the features card had been silently stuck on stale numbers for a full
  session with nobody noticing, because the auto-sync comment *claimed* it
  was working. Replaced both regexes with a `{{TOTAL_KITS}}` literal-token
  substitution (computed from a real `ui_kits/` directory scan, same
  discovery rule `scripts/a11y-audit.mjs` uses) that can't silently stop
  matching just because the surrounding prose gets reworded again.
- Category pill counts frozen, don't reflect the text filter — **DONE**.
  Verified live: typing a query that matches zero kits used to leave every
  pill showing its full unfiltered total. Pills now recompute from the
  text-filtered (not category-filtered) item set, so a pill's number tells
  you what selecting it would currently give you. Verified live: typing
  "zzzznomatch" now shows `All 0 / AI & Chat 0 / ...` across every pill.

## Section structure & headings (the other real structural bug)

- **DONE.** Verified live, before and after: heading order was H2("open")
  → H2("bins") → H2("More") → **H1**("Design") → **H3**("Live
  components") → H2("open") [again] → ... — three H2s before the page's own
  H1, and an H1→H3 skip immediately after it, both real per axe's own
  heading-order check being out of this repo's automated WCAG-tag scope
  (see the prior pass's a11y-report caveats).
  Root-caused and fixed at the component level, not just this one page:
  - `Side()` (`src/components/shell/app-shell.js`) rendered each sidebar
    group's label as `<h2>`. A sidebar nav group label is not page content
    — changed to a plain `<div>`; `role="group"`+`aria-labelledby` already
    gave it an accessible name regardless of the referenced element's tag,
    so no AT-facing behavior changed, only the content heading outline.
  - `Section()` (`src/components/content/panel.js`) hardcoded `<h3>` with
    no override, unlike its sibling `Panel()` (which already had a
    `headingLevel` prop defaulting to `h2`). Added the same
    `headingLevel = 2` default/override to `Section()` — fixes the H1→H3
    skip everywhere `Section` is used directly under a page's own H1, not
    just this one homepage call site.
  - Verified live (local-SDK test copy): heading sequence is now
    H1("247420") → H2("Live components") → H2("open") → ... — no premature
    headings, no skip.
- Two different H2s both read "open" — **DONE** as a side effect: the
  sidebar's "open" is no longer a heading at all, so there's only one real
  H2 "open" left (the tier eyebrow).
- Lowercase sentence-fragment subheads vs. sentence-case headings — **N/A**.
  Confirmed real (`client-script.js`'s `TIERS` array: "browse and try the
  system running.", etc.) but this is a deliberate, uniform style choice for
  this ONE specific role (tier ledes), not an accidental mix within a
  single heading level — left as-is, a copy-voice call for the maintainer.
- Centered→left alignment with no transition — **BACKLOG**, real but a
  layout-design decision, not a bug with one obvious correct fix.
- Full-height saturated green section rail — **BACKLOG**, same as above,
  a visual-design call.

## Theme system

- Focus ring `#fff` in both themes, invisible in light — **N/A, false**.
  Verified directly: `--focus-color` has exactly one definition site
  (`:root`, `var(--accent-ink)`) and resolves to `#001759` on paper,
  `#E8E9FF` on ink, `#58a6ff` on github-dark, `var(--green)` on thebird —
  never `#fff` anywhere. This was already fixed by the prior remediation
  pass (`--focus-color` used to reference the near-invisible `--accent` FILL
  token before that pass repointed it to `--accent-ink`); the audit's
  premise was stale.
- Theme toggle cycles with no next-state indicator; "stuck on auto" — TRUE
  cycle is `auto → paper → ink → auto` (not "light"), current-state display
  only, no next-state preview — **BACKLOG**, a real but small UX polish, not
  done this pass.
- Light theme loses panel-on-panel layering — **PARTIAL/BACKLOG**. Confirmed
  paper/paper-2/paper-3 are genuinely close (contrast ≈1.26:1 between
  extremes) — a real, subtle design characteristic, not obviously a "bug"
  with one correct fix; needs a design call on how much separation the
  light theme should carry, not done blind.
- Danger button "loud" light vs. "softer" dark — **N/A, false as framed**.
  Same CSS rule applies in both themes; only the underlying `--warn` color
  value changes per theme (as designed) — no structural weight difference
  exists to fix.
- `data-theme="auto"` no visible cue distinguishing from explicit dark —
  **PARTIAL/N/A**. A cue does exist, just narrowly: the compact toggle's
  tooltip appends "(currently dark)"/"(currently light)" when in auto mode.
  Not surfaced in the always-visible label — a real gap, but small; grouped
  with the toggle backlog item above rather than fixed in isolation.

## Metadata & polish

- `og:image` 404 (`/design/og-card.png`, file never existed) — **DONE**.

  real image configured, defeating `renderSeoTags()`'s own `image ? ... :
  ''` guard designed to omit the tag cleanly when there's nothing to point
  at. Now `image: site.image || ''` — no image configured, no tag emitted,
  no more broken card on every social/Slack/Discord share. Same fix applied
  to `scripts/generate-ui-kit-scaffolds.mjs`'s `seo.ogImage` path (2 kits
  had it set, both emitting the same dead link).
- Favicon "placeholder-tier" — **N/A**. It's a real minimal brand monogram
  (rounded green tile, "24" glyph), not a single bare character as
  originally framed — left as-is.
- `<title>` "design" lowercase vs. `<h1>` "247420"/"Design" — **DONE**.
  `site.yaml`'s `title` is now `"Design"`, sentence-cased consistently
  with the rest of the site's heading casing.
- Meta description lowercase/abstract — **DONE**. Rewritten to a concrete,
  fact-based sentence (component/kit counts, install method) instead of
  poetic/abstract phrasing — a real improvement for a search-result
  snippet.
- Inline `<svg>` missing `<title>`/`aria-hidden` — **N/A, false**. Every
  icon renders through the shared `iconAttrs()` helper, which always sets
  `aria-hidden="true"` — sampled 3, all consistent.
- Hardcoded pink `rgba(232,75,138,...)` debug grid overlay — **DONE**.
  The rule's own comment already called it a "mascot grid"; it just never
  actually referenced `--mascot`. Now `color-mix(in oklab, var(--mascot)

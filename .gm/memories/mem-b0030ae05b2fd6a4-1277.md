gm-method: on Windows, the browser verb's 'url=<target>\ncapture\n<script>' shorthand can silently fail to attach page context before eval, producing a persistent 'ReferenceError: document is not defined' and/or a native 'UV_HANDLE_CLOSING' assertion crash that poisons the session id (every subsequent dispatch reports the same session_id with the same failure, even after 'session new'). Recovery that actually works: (1) find and kill the playwriter relay process via Win32_Process CommandLine match on 'playwriter', (2) kill all chrome.exe processes for a clean slate, (3) dispatch 'session new' to get a genuinely fresh session id (confirm the id number changed), (4) switch the script body from the 'url=/capture' shorthand to the native Playwright API form: 'await page.goto(url, {waitUntil:\"load\"}); await page.waitForTimeout(N); const result = await page.evaluate(() => {...}); console.log(JSON.stringify(result));'. The native page.goto/page.evaluate path works even when the shorthand path is broken on that host/build. Bare-word bodies like 'reset' or 'close' are NOT special commands in this verb -- they get eval'd as JS and throw ReferenceError; only 'session new'/'session close' (with the literal 'session' prefix) are recognized session-management commands.

gm browser verb bug: a LITERAL COLON anywhere in the script body makes the dispatch fail with cdp-eval SyntaxError Unexpected token. The prefix parser splits the body on any colon, including inside string literals, object literals and ternaries. Verified: body [return "a:b"] FAILS; body [return "a"+String.fromCharCode(58)+"b"] returns a:b correctly. Consequences: you cannot write var x={a:1} or an https URL in the body. Workarounds: use the url= PREFIX for navigation (its colon is consumed before the split), build any needed colon with String.fromCharCode(58), and construct objects by property assignment (var o=JSON.parse(String.fromCharCode(123,125)); o.k=v) or return arrays instead of object literals. Root fix belongs in crates/agentplug-host/src/browser.rs so it splits only on a known prefix token at line start.

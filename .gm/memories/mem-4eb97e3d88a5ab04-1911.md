anentrypoint-design marketing site composition (2026-07-29, commit 4c2555c): the homepage rendered its nine content panels as a FLAT concat in src/page-html/client-script.js mainChildren, so every panel was a peer under .app-stage single uniform grid gap. Measured live at 1040px: stage 11156px = 17.2 screens, panel heights [2555,1472,1016,782,560,487,436,388,308,191] -- a 13x spread given identical 48px separation, so proximity communicated nothing. Fix was NOT widening: .app-stage max-width computes min(96%,1600px) which NEVER BINDS at 1040 because 324px of the 1040 is chrome (220px .app-side-shell + .app-main 32px x2 + .app-stage 24px x2), leaving a 716px stage; an experiment removing the cap entirely gained only 30px. Real fix is composition -- panels resolve by id into three tiers (open: kits/previews/decks/examples, ships: file_browser/desktop_os/web_components/api_exports, read: docs/features/quickstart) with non-uniform rhythm: 16px within a tier, 32px margin between tiers ON TOP of the stage 48px gap. Result 11156->8911px, 17.2->13.7 screens, tallest 2555->1580. Two non-obvious traps hit: (1) a .ds-tier-open > .panel:first-of-type spine selector silently does NOT match because the tier head div is the first child and shares the div type -- use an explicit class applied in JS instead; (2) the tier label must be a real h2 with aria-labelledby on the section, otherwise the three section landmarks are unnamed in the AX tree even though they read fine visually. Row code ordinals (01,02,03) on kits/previews/examples were dropped (85 codes -> 25) because they restated position the DOM order already carries; the surviving codes (md,css,fb,os,wc,api) are TYPE tags and do carry information. Theme feeds panels via site/theme.mjs which needed explicit id args -- home.yaml sets no section id, so the tier lookup by id silently matched nothing until panel(section,id) passed a fallback.

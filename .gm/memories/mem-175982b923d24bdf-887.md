gm-method: codesearch is a fusion-embedding index, not literal grep -- querying exact tokens like 'TODO' or 'FIXME' returns semantically-similar code (icon helpers, theme functions) ranked by cosine similarity, not literal substring matches. A TODO-sweep task needs MULTIPLE distinct phrasing queries (comment-style, stub-style, no-op-style, unimplemented-warning-style) to triangulate a true negative, since any single query's absence of hits is weak evidence on its own -- convergent zero-hits across 5+ differently-phrased queries is the actual signal. When a borderline candidate surfaces (e.g. a function returning fixed/synthetic data), read the full file before concluding stub vs. legitimate: self-declared demo/preview code often contains explicit disclosure text in its own UI copy (a lede paragraph, a dialog message, a status bar) that settles the ambiguity without guessing.
